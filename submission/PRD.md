# PRD｜TradingAgents 多视角 AI 投研助手

> 文档版本：MVP v1.0
> 产品阶段：课程实战原型
> 核心原则：个性化解释，不个性化事实
> 风险声明：本产品提供投研信息与决策支持，不构成投资承诺或自动交易指令。

## 1. 一句话产品定义

面向缺乏专业投研背景的普通自主投资者，通过 TradingAgents 将行情、新闻、公告、基本面与市场情绪压缩为专业分析报告，再由多视角 Agent 协作室同时呈现支持、反对和风险证据，并结合用户个人画像用其能理解的语言解释，帮助用户在十分钟内形成可解释、可反思的自主投资判断。

## 2. 背景、问题与证据边界

### 2.1 题面事实

- 普通投资者每天面对实时行情、财经新闻、上市公司公告、券商研报摘要与社交平台讨论等碎片化信息。
- 用户既难以理解专业表述，也难以判断哪些信息真正影响自己关注的标的。
- 现有资讯工具主要负责推送，信息消化和判断仍由用户完成。
- 用户得到分析后会继续追问“现在该买还是该卖”；当 AI 语气确定时，部分用户可能据此交易。
- 用户往往难以区分对话中已经发生的事实与对未来的推断。
- 平台可调用实时及历史行情、财经新闻和上市公司公告，并可使用用户自选股及历史浏览记录作为个性化输入。

### 2.2 合理推断

- 用户需要的不是更多信息，而是“与标的有关的关键变化—依据—影响—反面证据—失效条件”。
- 专业报告能够降低信息噪音，但单一 AI 的最新结论仍可能造成结论锚定。
- 多视角 Agent 的价值不在于多数投票，而在于让关键分歧和判断前提可见。
- 用户画像能降低理解门槛，但不应改变市场事实或迎合用户已有立场。

### 2.3 待验证假设

- TradingAgents 的多 Agent 分析能比普通资讯列表保留更多关键事件并减少无关信息。
- 同时展示支持、反对和风险证据，能降低用户对单一买卖结论的依赖。
- “事实/推断/未知/失效条件”的结构能提高普通投资者对结论边界的理解。
- 用户愿意查看、修正并授权使用个人投研画像。
- 用户愿意在高风险买卖问题中补充持仓状态、投资周期和风险承受能力。

## 3. 用户分层与核心用户

| 用户层 | 关键任务 | 痛点强度 | 使用频率 | 产品价值 | 是否核心 |
|---|---|---:|---:|---:|---|
| 投资入门者 | 看懂市场事件和基础术语 | 高 | 中 | 降低理解门槛 | 次核心 |
| 普通自主投资者 | 对 3–20 只自选股持续跟踪并形成判断 | 高 | 高 | 降噪、对照观点、辅助决策 | **核心** |
| 专业/高频投资者 | 快速执行成熟策略 | 中 | 高 | 现有专业终端替代性强 | 非核心 |

核心用户选择理由：普通自主投资者既有持续投研需求，又缺少覆盖行情、基本面、新闻和风险的完整框架；其单一结论锚定风险明显，同时适合通过一次完整问答场景展示 Agent 的价值。

## 4. 核心场景与产品核心卡

### 4.1 核心场景

工作日晚间，用户发现自选股出现明显涨跌或重要新闻，希望在十分钟内判断“发生了什么、原有投资逻辑是否变化、现在有哪些支持与反对证据”。过去用户会在多个平台来回搜索，或直接问单一 AI“该不该买”，容易忽略相反证据并把未来推断误当事实。本产品先生成多 Agent 专业报告，再在协作室中基于同一份报告提供多视角解释与用户确认。

### 4.2 产品核心卡

| 项目 | 当前产品基线 |
|---|---|
| 核心用户 | 关注 3–20 只股票、缺乏完整专业投研框架的普通自主投资者 |
| 触发场景 | 自选股异动、重大新闻或财报后，需要快速判断投资逻辑是否变化 |
| 用户目标 | 看懂关键变化、支持与反对证据，并形成自己的下一步判断 |
| 当前做法 | 浏览多个资讯平台、阅读碎片摘要或直接询问单一 AI |
| 最大痛点 | 信息噪音高；专业表述难懂；最新单一结论容易形成锚定 |
| Agent 核心价值 | 多步骤调用异构数据并综合判断；同时暴露多种立场和不确定性；根据用户认知调整解释 |
| Demo 核心时刻 | 用户问“现在该买吗”，不同角色给出有依据的多空与风险观点，个人助手再区分事实、推断、未知和失效条件 |
| 成功标准 | 用户能复述至少一条支持证据、一条反对证据和一个结论失效条件，而非只记住 BUY/SELL |

## 5. 产品定位与成立判断

### 5.1 产品定位

本产品是“面向普通投资者的多 Agent 投研决策支持工具”，不是资讯聚合器、荐股机器人或自动交易系统。它在资讯与交易决定之间增加两层价值：

1. **专业信息降噪**：TradingAgents 多 Agent 链将分散信息整理成结构化投研报告。
2. **多视角决策去偏**：协作室从基本面、市场、研究综合及风险等角度解释同一份报告，个人助手负责认知适配和用户确认。

### 5.2 为什么需要 Agent

该任务同时包含自然语言意图识别、多源非结构化信息处理、动态数据工具调用、多步骤研究辩论、基于证据的综合判断和交互式澄清，固定规则或单轮问答难以形成完整闭环，因此具备使用 Agent 的必要性。

### 5.3 产品成立条件与否决条件

| 判断维度 | 成立条件 | 不成立/需暂停上线的信号 |
|---|---|---|
| 降噪价值 | 关键事件召回率不低于 90%，保留信息相关率不低于 80% | 关键公告持续遗漏，或报告与资讯列表一样冗余 |
| 可信表达 | 事实可追溯，推断和未知被显式标注 | 出现无依据确定性结论，或引用无法支撑结论 |
| 去偏价值 | 用户能识别多空分歧和失效条件 | 多 Agent 只是重复观点，或形成“多数即正确”的权威错觉 |
| 个性化价值 | 同一事实可按用户认知水平准确转译 | 为迎合用户偏好而改变证据权重或分析结论 |
| 用户控制 | 画像可查看、修正、关闭；高风险决策需要确认 | 系统暗中推断风险承受能力或替用户执行交易 |

## 6. 产品目标与非目标

### 6.1 MVP 目标

- 让用户从自选股出发完成一次“提问—分析—多视角追问—个人总结—用户确认”的闭环。
- 让评审看见 TradingAgents 的角色分工、数据依据和结果检查，而不是只看到一个聊天框。
- 让专业结论以普通用户可理解的语言呈现，同时保留原始证据和不确定性。

### 6.2 非目标

- 不提供收益保证、价格目标承诺或无条件买卖指令。
- 不自动执行真实或模拟交易；本次 MVP 移除模拟交易模块。
- 不建设完整券商账户、资产配置或社区功能。
- 不把浏览行为直接解释为风险承受能力、财务状况或真实持仓。
- 不以 Agent 数量投票决定最终结论。

## 7. MVP 功能

| 优先级 | 功能 | 对应痛点 | 用户价值 | Demo 覆盖 |
|---|---|---|---|---|
| P0 | AI 自选股与个人投研画像 | 每次都要重复说明关注标的和理解水平 | 持续沉淀关注与认知上下文 | 是 |
| P0 | TradingAgents 多 Agent 投研分析 | 信息分散、噪音高、缺少专业框架 | 形成可追溯的专业分析报告 | 是 |
| P0 | 个性化多 Agent 协作室 | 单一结论锚定、专业内容难懂 | 同时看见多空风险，并获得适配解释 | 是 |

### 7.1 AI 自选股与个人投研画像

用户可以添加/删除自选股，查看最近浏览和最近分析。系统可基于站内行为提出“建议加入自选”，但必须由用户确认。

个人画像分三类：

| 类型 | 示例字段 | 更新规则 |
|---|---|---|
| 用户明确设置 | 知识水平、常用投资周期、关注方向、解释偏好、常用市场 | 用户主动设置或确认后更新 |
| 行为记录 | 自选股、浏览记录、高频标的、已读报告、常用单聊角色 | 记录产品内行为；用户可查看、删除或关闭 |
| AI 推测标签 | 偏好基本面、可能不熟悉估值术语、经常关注风险 | 必须标注“AI 推测”，允许确认、修改和删除 |

风险承受能力、资产规模、持仓成本和真实持仓不得仅从浏览记录推断。高风险买卖问题缺少相关信息时，由个人助手当次询问。

### 7.2 TradingAgents 多 Agent 投研分析

用户选择股票、日期、分析深度和关注方向后，系统调用 TradingAgents 原生流程：

1. 市场、情绪、新闻、基本面分析师并行形成专业报告。
2. 多头与空头研究员辩论，研究经理形成研究判断。
3. 交易员形成条件化方案。
4. 激进、中性、保守风险分析师进行风险辩论，投资组合经理形成最终裁决。

报告展示分析时间、数据状态、各角色产出、支持与反对证据及限制。真实接口不可用时，不得用预置内容冒充实时结果。

### 7.3 个性化多 Agent 协作室

协作室包括一个总工作群和用户与各角色的单聊窗口。

- **总工作群**：个人助手按问题类型调度相关角色；用户看到 9 个职责清楚的产品角色，但不要求每次全部发言。后台原生辩论节点不会拆成大量聊天成员。
- **单聊**：角色仅在自身职责范围内回答；超出范围时引导至相应角色。
- **买卖问题**：至少调度研究员和风险分析师；研究员内部呈现正反逻辑，风险分析师内部呈现三种风险情景，个人助手最后总结，不进行多数投票。
- **回答依据**：先从同一次 TradingAgents 报告中检索对应角色段落及证据，再生成回答，不只检索最终 BUY/SELL/HOLD 标签。

## 8. Agent 角色映射

| 阶段 | 用户可见产品角色 | TradingAgents 后台角色 | 主要职责 |
|---|---|---|---|
| 信息分析 | 市场分析师 | Market Analyst | 价格趋势、成交量、技术指标 |
| 信息分析 | 情绪分析师 | Sentiment Analyst | 社交讨论与市场情绪；不把热度当价格预测 |
| 信息分析 | 新闻分析师 | News Analyst | 公司新闻、宏观信息和事件影响 |
| 信息分析 | 基本面分析师 | Fundamentals Analyst | 财务、业务与估值相关事实 |
| 研究辩论与裁决 | 研究员 | Bull Researcher + Bear Researcher + Research Manager | 同时呈现支持逻辑、反对逻辑、核心分歧与研究结论 |
| 交易方案 | 交易员 | Trader | 将研究判断转成条件化行动方案 |
| 风险辩论 | 风险分析师 | Aggressive Analyst + Neutral Analyst + Conservative Analyst | 汇总乐观、基准、保守情景和最大下行风险 |
| 最终裁决 | 投资组合经理 | Portfolio Manager | 综合交易方案与风险辩论 |
| 用户交互 | 个人助手 | 产品新增，非原生角色 | 理解用户、调度角色、适配表达、汇总分歧、发起确认 |

个人助手不重新计算股票结论，也不冒充专业分析师；其创新价值是把专业报告转换为适合当前用户理解和判断的表达。前台角色合并只减少用户认知负担，不删除 TradingAgents 后台的多空辩论、研究经理裁决或三类风险讨论。

## 9. 端到端交互与人机协作

| 步骤 | 用户行为 | AI 自动完成 | 是否需用户确认 |
|---|---|---|---|
| 1. 进入任务 | 从自选股选择股票或输入代码和问题 | 加载授权的画像、自选股与浏览上下文 | 股票代码、分析日期需可见 |
| 2. 检查信息 | 提出“为什么跌/该不该买”等问题 | 识别意图、检查数据和个人信息是否充分 | 买卖类问题缺少周期、持仓或风险信息时必须补充 |
| 3. 专业分析 | 选择分析深度或使用默认值 | 调用数据工具和 TradingAgents 分析链 | 刷新分析前由用户触发 |
| 4. 报告检查 | 查看分析进度 | 检查关键报告、时间戳和证据是否可用 | 数据不足时由用户选择补充、重试或查看降级结果 |
| 5. 多视角追问 | 在总群或单聊提问 | RAG 检索同次报告，相关角色并行回应 | 无需逐条确认 |
| 6. 个人总结 | 阅读共识、分歧和条件 | 按画像转译术语，区分事实/推断/未知 | 用户确认理解、继续追问或结束 |
| 7. 画像沉淀 | 纠正偏好或 AI 推测 | 保存已授权的行为记录 | AI 推测标签和风险偏好必须由用户确认 |

## 10. 用户画像使用规则

所有 Agent 接收统一的“用户上下文包”，包括用户明确设置、授权的站内行为、本次任务信息和禁止推断字段。

每个专业 Agent 的输出分为两层：

1. **专业分析层**：仅由数据和报告证据决定，不受用户偏好影响。
2. **用户解释层**：参考知识水平、关注周期和解释偏好，调整术语、详略、举例和信息顺序。

示例：专业结论“毛利率同比下降 3.2 个百分点，若下一季度未恢复，盈利预测存在下修风险”，对入门用户可解释为“公司每卖出 100 元产品，留下的毛利比去年少约 3.2 元；如果下季度仍未改善，市场可能下调对未来利润的预期”。事实与判断边界不变，只改变表达方式。

## 11. 可信表达协议

### 11.1 专业 Agent 回答结构

```text
角色视角：我从哪个专业角度回答
已确认事实：报告或数据已经支持的内容
分析推断：基于事实得到、但尚未发生的判断
相反证据：可能推翻或削弱当前判断的信息
关键假设：判断成立依赖什么前提
失效条件：出现什么情况需要重新评估
置信度：高/中/低及原因
报告依据：对应报告段落、数据时间或证据编号
```

### 11.2 个人助手总结结构

```text
与你相关的核心问题
已确认事实
Agent 共识
关键分歧
仍然未知
支持行动的条件
应等待或重新评估的条件
需要你确认的信息
```

置信度表示“当前证据对判断的支持程度”，不表示收益概率，也不能替代风险承受能力判断。

## 12. 信息架构与页面范围

| 页面 | MVP 内容 |
|---|---|
| 工作台 | 自选股、最近浏览、待关注事件、最近分析 |
| 股票分析 | 标的与参数输入、Agent 实时进度、结构化报告 |
| Agent 协作室 | 总工作群、角色单聊、报告依据、个人助手总结 |

模拟交易页面、模拟账户资产和下单入口不在 MVP 中。

## 13. 数据、知识与技术边界

- 专业分析使用 TradingAgents 当前支持的行情、技术指标、基本面、新闻、宏观和市场情绪工具；实际可用性以运行环境为准。
- 协作室 RAG 的知识边界是“当前选中标的、当前分析批次的结构化报告”，避免跨日期或跨标的混用。
- 每个检索片段携带标的、分析批次、角色、报告章节和时间戳。
- 用户画像仅使用用户明确设置及其授权的产品内数据；不得导入未授权外部隐私数据。
- 分享版默认展示明确标注的预置交互案例数据；实时模式的模型密钥只能保存在后端环境变量中。

## 14. 验收标准与成功指标

| 层级 | 指标/标准 | MVP 最低目标 | 验证方式 |
|---|---|---:|---|
| 用户价值 | 用户可复述支持证据、反对证据、失效条件各 1 条 | 任务可完整走通 | 5 个可用性任务，后续执行 |
| 降噪效果 | 关键事件召回率 | ≥90% | 专家标注原始信息集与报告对照 |
| 降噪效果 | 保留信息相关率 | ≥80% | 专家逐条标注报告信息相关性 |
| 可信度 | 事实与引用一致率 | ≥95% | 事实声明回查原始来源 |
| 可信度 | 事实/推断/未知标注准确率 | ≥90% | 双人标注加分歧复核 |
| 去偏效果 | 关键相反证据覆盖率 | ≥90% | 与多空证据金标对照 |
| 安全边界 | 无依据确定性买卖结论 | 0 次 | 对抗性问题测试 |
| 用户控制 | 买卖问题必要确认触发率 | 100% | 流程埋点与测试用例 |
| 个性化 | 画像可查看、修正、删除、关闭 | 100% 可操作 | 功能验收 |

以上数值为上线前建议门槛，不是本次已完成的实测结果；实际测试结果将在验证报告中单独记录。

## 15. 主要风险与缓解方式

| 风险 | 影响 | MVP 缓解方式 |
|---|---|---|
| 多 Agent 形成群体权威感 | 用户把多数意见当正确答案 | 禁止投票式结论；必须展示关键分歧和反证 |
| 专业角色重复表达 | 多视角只有形式差异 | 为角色限定问题、证据范围和输出协议 |
| 数据过期或接口失败 | 把历史信息误作当前事实 | 展示时间戳；结果检查失败时进入统一降级分支 |
| RAG 截断上下文 | 引用片段无法支撑回答 | 检索章节级上下文并回链原报告 |
| 画像造成迎合偏差 | 强化用户原有立场 | 专业分析与用户解释分层；画像不改变证据权重 |
| 用户忽略风险提示 | 直接依据结论交易 | 高风险问题强制确认；不自动交易；展示失效条件 |

## 16. 后续方向与基金场景迁移

后续可增加真实后端部署、关注事件提醒、报告版本对比和用户理解度反馈，但不在本次 MVP 范围内。

迁移到基金解读时不能直接复用个股假设，需要重新定义：

- 分析对象由单一公司变为一篮子资产、基金经理与投资策略。
- 实时价格重要性下降，净值披露频率、持仓滞后和风格漂移重要性上升。
- 基本面 Agent 需改为组合穿透、行业暴露、费用与基金经理分析。
- 技术信号、新闻相关性和失效条件的时间尺度需重新标定。
- 买卖问题需增加申赎费用、封闭期、流动性、跟踪误差和用户整体资产配置约束。

## 17. Demo 范围

Demo 默认采用一组明确标注的预置交互案例数据，完整展示“自选股进入—加载画像—TradingAgents 进度与报告—协作室买卖追问—多视角回答—个人助手总结—用户确认”。本地环境可保留实时分析能力，但分享版不要求评审输入 API Key，也不把预置案例伪装成真实运行或实时结果。
