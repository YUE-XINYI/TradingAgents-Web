description 产品与交互方案说明

AI投研助手

面向缺乏完整投研框架的普通自主投资者，TradingAgents 负责把碎片化市场信息压缩成专业报告；多视角协作室让相反证据同时可见；个人助手再用用户能理解的语言解释，但不替用户做交易决定。

10 分钟 目标：从异动提问到形成可解释判断
9 个角色 前台聚合展示，后台保留完整辩论链
0 次代客交易 系统止于决策支持，最终行动由用户确认

01 / POSITIONING

它是什么，也明确不是什么

产品位于资讯工具与交易决策之间，核心不是继续增加信息，而是帮助用户建立可复述、可质疑的判断。

person

服务谁

关注 3–20 只股票、会主动研究，但缺乏行情、基本面、新闻与风险完整框架的普通自主投资者。

核心用户 高频持续需求
filter_alt

解决什么

把“发生了什么、为什么重要、有哪些反证、何时失效”串成一条证据链，降低信息噪音与单一结论锚定。

专业降噪 多视角去偏
block

不做什么

不做资讯搬运、荐股机器人、收益承诺或自动交易系统；不以 Agent 数量投票，也不从浏览记录推断真实持仓与风险承受力。

决策支持 ≠ 投资指令

02 / VIABILITY

结论：产品有条件成立

需求成立来自题面观察；产品价值与安全性仍需用上线前指标验证，不能把方案假设写成已验证事实。

GO · 进入验证 有条件成立 先验证降噪与可信表达，再决定是否上线。
  • check_circle 问题真实：用户面对碎片信息，现有推送工具没有替其完成消化与判断。
  • check_circle Agent 必要：任务需要意图识别、多源工具调用、多步骤综合判断、辩论与交互澄清。
  • check_circle 差异明确：TradingAgents 解决专业降噪，协作室解决单一结论锚定，个人助手解决理解门槛。
  • check_circle 边界可控：高风险问题强制补充上下文，不自动交易，并展示证据时间与失效条件。

03 / INTERACTION PATH

从一句提问到可解释结论

点击左侧步骤查看责任与输出。主路径在“AI 自动处理”和“用户关键确认”之间交替，而不是把全部控制交给模型。

STEP 01

用户发起问题

用户主导

用户从 AI 自选股进入，或输入股票代码、分析日期与自然语言问题。系统展示将要分析的标的和数据窗口，避免跨标的或跨日期误用。

交互原则：低风险步骤由 AI 自动推进；会改变分析对象、使用隐私数据或可能影响现实交易的步骤，由用户确认。

04 / PRODUCT SCREENS

四个页面承载一条完整的人机协作路径

页面不是彼此独立的功能集合：工作台定义任务，分析记录呈现 AI 的研究过程与依据，协作室帮助用户挑战结论，“我的投研”则把用户确认过的解释偏好带回下一次任务。

01 · 用户输入 工作台 确认标的、日期、研究深度与重点，主动发起分析。
02 · AI 研究 分析记录 自动运行多 Agent 链，展示进度、摘要、依据和边界。
03 · 人机协作 协作室 用户追问和质疑，AI 调度角色呈现分歧并补问约束。
04 · 用户控制 我的投研 用户修正解释偏好与授权，影响表达但不改变事实。
01 · 工作台

用户定义问题，AI 不替用户猜任务

用户输入股票代码，并确认研究深度、分析日期和重点关注方向。点击“开始多 Agent 分析”才会创建新任务；AI 同时加载已经授权的自选股、浏览记录和画像上下文。

用户负责：确认标的、时间窗口与研究目标。
AI 负责：组合授权上下文、识别问题并规划研究范围。
页面输出：边界清晰、可以执行的一次分析任务。
02 · 分析记录

AI 自动研究，但过程、证据和限制全部可见

TradingAgents 自动完成多源数据调用、四类分析师并行研究、多空辩论、交易方案和风险裁决。用户无需逐步操作，但可以看到完成进度、数据窗口、个人助手摘要和原始角色报告。

AI 负责：专业分析、结果检查、结构化报告与角色级索引。
用户负责：核对“非实时”标识、事实与推断，并决定是否继续追问。
质量闸门：关键数据缺失时缩小结论，不补造完整答案。
03 · 协作室

把单一答案改成可追问的多视角判断

用户可在总工作群询问“为什么涨”或“现在适合买入吗”。个人助手根据意图调度相关角色；所有回答仅检索当前标的、当前分析批次的报告。研究员呈现正反逻辑，风险分析师呈现三种情景，最后由个人助手整理边界。

用户负责：追问、质疑依据，并补充持仓、周期和风险边界。
AI 负责：按问题路由角色，区分事实、推断和未知。
决策原则：角色分工不等于多数投票，最终现实行动仍由用户决定。
04 · 我的投研

用户控制画像，画像只改变解释方式

用户可设置先结论还是先证据、常用关注周期、优先关注维度和专业术语偏好，并可关闭个性化解释与浏览记录授权。下一次对话读取这些设置，但专业报告仍由数据与证据决定。

用户负责：查看、修改、删除或关闭画像及数据授权。
AI 负责：只调整术语、信息顺序、详略与举例。
禁止推断：资产规模、真实持仓、成本和风险承受力不得由浏览记录推出。

05 / AGENT SYSTEM

专业降噪不是一个按钮，而是一条研究链

本方案不额外包装独立“过滤器”。信息在专业分工、正反辩论、风险压力测试和最终裁决中逐层被筛选与压缩。

06 / HUMAN–AI

哪些自动完成，哪些必须让用户参与

自动化负责降低操作成本；确认点负责避免隐私越界、数据误用与高风险决策被模型替代。

环节 AI 自动完成 用户参与／确认 责任归属
任务进入 加载已授权的自选股、浏览记录与画像 确认股票代码与分析日期 人机协作
意图检查 识别问题类型与必要信息 买卖问题补充持仓、周期和风险边界 人机协作
专业研究 调用数据、并行分析、辩论、压力测试与报告检查 主动触发刷新；失败时选择重试或有限结论 AI 执行
协作追问 检索同次报告、路由相关角色并生成差异化回答 选择总群或单聊，并继续追问 人机协作
可信总结 转译术语，汇总事实、推断、未知与失效条件 确认理解，纠正画像或补充个人信息 人机协作
现实行动 不下单、不保证收益、不替用户承担风险 决定是否继续研究或采取任何投资行动 用户决定

07 / TRUST LANGUAGE

让结论自带边界，而不是只附免责声明

每次专业回答都遵循统一协议；置信度表示证据支持程度，不是收益概率。

已确认事实

报告或数据已支持的内容，附数据时间、章节或证据编号，可回查来源。

分析推断

从事实推出但尚未发生的判断，必须同时说明依赖的关键假设。

仍然未知

数据未披露、个人信息未确认或报告未覆盖的内容，不能用猜测补齐。

失效条件

出现后必须重新评估的可观察信号，防止用户把旧结论长期固化。

“当前报告支持的是 HOLD／条件观察，不是对你的个人买卖指令。”

09 / GO–NO GO

上线前最低验证门槛

以下为建议门槛，并非本次原型已经取得的实测成绩；完整方法与样本设计在评估方案中说明。

≥ 90% 关键事件召回率 若持续遗漏关键公告，则降噪价值不成立
≥ 80% 保留信息相关率 若报告仍与资讯列表同样冗余，则暂停上线
≥ 95% 事实与引用一致率 任何关键事实必须能由引用直接支撑
≥ 90% 事实／推断／未知标注准确率 由双人标注并对分歧复核
≥ 90% 关键相反证据覆盖率 防止多 Agent 只重复同一方向观点
0 次 无依据确定性买卖结论 买卖问题必要确认触发率必须为 100%

10 / BOUNDARY

能力边界与失败时的行为

“知道自己不知道什么”是产品可信度的一部分。接口失败或证据不足时，系统缩小结论，而不是补造完整答案。

check_circle Agent 可以

  • 整理多源信息并提取与标的相关的关键变化
  • 运行多角色研究、辩论、压力测试与结果检查
  • 展示支持证据、反对证据、假设和失效条件
  • 根据用户画像调整术语、顺序、详略与举例
  • 数据不足时说明缺失、影响范围与下一步选择

cancel Agent 不可以

  • 把历史案例冒充实时行情或把推断写成事实
  • 隐藏关键反证，或用发言人数决定结论
  • 从浏览记录推断资产规模、持仓成本或风险承受力
  • 保证收益、给出无条件买卖指令或自动执行交易
  • 在引用不支持结论时维持确定性表达
warning
统一降级： 明确指出缺失的数据源、受影响的判断和数据时间；用户可以补充信息、重试、查看有限结论或结束。分享版 Demo 使用预置案例数据，并始终标注“非实时”。
